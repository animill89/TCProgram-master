AI + 旅行 · 毕设产品方案 · 多人群聊出行场景
程星AI · 群聊成行
把微信群里的"旅行闲聊"，变成一份可直接下单的多人出行方案 —— 自动识别人数、日期、城市，生成含酒店、火车票、打车、门票的完整方案，并实时计算人均均摊价格。

方向：行前决策辅助（多人出行）
载体：微信小程序 / App · 程星AI
品类交叉：酒店 × 火车票 × 用车 × 门票
核心能力：聊天记录解析 + 方案生成 + 均摊计算
一、这个 Demo 是什么
一句话定义：一个把「微信群聊天记录」直接翻译成「可下单出行方案 + 人均价格」的 AI 助手。

用户在群里讨论旅行的过程，本身就是一次非结构化的需求表达——"十一咱们去杭州吧""我带娃""人均别超600""高铁还是开车？"。这些信息今天全部沉淀在聊天记录里，没有任何产品能把它们利用起来。

「群聊成行」提供两种入口，把这段聊天直接送进程星AI：

方式一：群聊多选转发
用户在微信群长按消息 → 多选聊天记录 → 转发到「程星AI」小程序/App → 直接进入程星AI界面，AI 自动识别人数、日期、城市等必要条件。
方式二：程星AI 内反向选取
用户打开微信小程序的程星AI页面 → 点「+」→「从聊天记录选择」→ 多选群聊消息 → 同样完成导入解析。
识别完成后，AI 生成完整出行方案（酒店 / 火车票 / 市内打车 / 门票），并按多人均摊规则计算出人均价格，分享回群里供全员确认，最终一键分账预订。

演示主线：一段真实的群聊截图（20+条杂乱讨论）→ 转发进程星AI → 10秒出「8人 · 10.2-10.4 · 杭州 · 人均¥1,675」的完整方案 → 分享回群 → 一键预订。用户全程不需要手动填任何表单。
二、痛点：多人出行的"规划断层"
痛点从哪来
单人订行程，OTA 已经解决得很好；但多人出行（家庭聚会、朋友结伴、团建小分队）的决策发生地在微信群，不在 OTA。规划过程被切散在几百条聊天记录里：

信息散落：人数、日期、目的地、预算、偏好分散在上百条消息里，谁也说不清"我们到底定下来没有"，同一个问题在群里被反复问。
组织者过劳：总有一个人被迫当"人肉规划员"——爬楼整理结论、比价、算账、订票、催钱。这是典型的义务劳动，且极易出错（漏订一个人的票、算错账）。
算账尴尬：8个人、4间房、2个儿童半价票、打车怎么摊？群收款只能收固定金额，"每人到底该出多少"靠组织者口算，算错一次就伤感情。
决策反复：群里"改到下周吧""还是去苏州？"——每改一次，组织者全部重来一遍。
影响了谁
组织者（发起人）：承担90%的整理、比价、订票、收账工作，体验最差、最容易被埋怨。
参与者：信息不对称，怕被"代表"，到最后才知道行程和花多少钱。
平台（同程）：交易决策发生在微信里，平台被排除在决策链路之外，只能承接最后一步的下单，没有渗透率、没有连带销售机会。
为什么值得做
60%+

4-7品类
一次多人出行平均牵动的品类数：火车票+酒店+门票+用车+餐饮
3-14天
多人出行从群里发起讨论到最终成行的典型决策周期
0
目前把"群聊记录"作为输入源的 OTA 产品数量
决策周期长、客单价高（一单8人×2晚×多品类 ≈ 万元级）、且决策完全发生在站外——谁把这段"站外决策"搬进站内，谁就拿到整个多人出行市场的入口。

三、目标用户
👨‍👩‍👧 家庭亲子群（核心）
三代/两家结伴出行，带娃约束多（儿童票、亲子房、行程不能太累），对"算清账"敏感度中等、对"省心"敏感度极高。
🎉 朋友结伴群（高频）
25-35岁朋友同事群，AA文化强，对"人均多少钱"是第一决策要素，价格敏感、决策反复多。
🏢 小型团建组织者（高客单）
10-20人的部门团建，组织者是被指派的HR/行政，最痛恨整理需求和收钱，付费意愿反而最强。
为什么选他们：三类用户的共同特征是——决策地=微信群、参与人≥2、必跨品类、必算账。这正是聊天记录解析+均摊计算最能发挥的场景。首发聚焦"组织者"这个角色：他是痛点最深的人，也是传播方案回群的执行人。

4.2 AI 四层能力架构
层级	做什么	技术实现	为什么必须用 AI
L1 非结构化解析	从杂乱聊天记录中抽取必要三要素（人数、日期、城市）与偏好要素（预算、带娃、住宿偏好、忌口、交通方式倾向）	LLM 信息抽取（NER + 槽位填充），输出结构化 JSON	聊天是口语、有错别字、上下文指代（"就定上周说的那个周末"）——规则和关键词永远覆盖不了
L2 澄清反问	识别信息缺口与冲突（"8人"里含几个儿童？两拨人说的日期不一致），用一句话追问，支持用户直接回答	LLM 对话式澄清 + 置信度阈值触发	直接生成会出错；先问再生成，把准确率从"碰运气"变成"可确认"
L3 方案生成	基于结构化要素，生成含酒店（多间房拆分）、火车票（成人+儿童票）、市内打车（行程预估）、门票（含儿童半价规则）的完整方案，Day by Day 编排	LLM 编排 + 供应链实时接口（房态/票价/余票/门票政策）+ 约束求解（时间不冲突、带娃过滤）	多约束（时间窗、体力、儿童限制、雨天备选）的编排是组合问题，人工要排2小时，AI 秒级给解
L4 均摊与协商	按均摊规则计算人均价格；群成员提出修改时（"Day2换西溪湿地？"）自动重算方案与价格并说明变化	规则引擎（分摊计算）+ LLM（改案理解 + 差异说明生成）	"改一处、全局价格重算+说明"只有 AI 能做到实时且让所有人看懂
4.3 均摊计算规则（Demo 核心亮点）
品类	均摊规则（默认）	可切换
酒店	按房间数拆分到"同住小组"，组内均摊（如4间房×2晚，每间对应2人）	全员均摊 / 按家庭为单位
火车票	成人全价、儿童按铁路儿童票规则半价，按人头各付各的	全员均摊
市内打车	按行程总预估 ÷ 总人数均摊	按家庭 / 按实际乘坐分段
门票	成人票 / 儿童半价票 / 老人免票，按人头计算，均摊或各付	免票人群自动剔除
输出示例：「8人 · 2晚 · 杭州：酒店 ¥5,600（4间家庭房）+ 门票 ¥3,240（含2名儿童半价）+ 火车票 ¥3,760 + 打车 ¥800 = 总价 ¥13,400，人均均摊 ¥1,675」——所有明细可展开、可切换分摊口径、可一键生成群收款。

五、创新点（vs 同程及竞品已有功能）
创新1输入源创新：聊天记录即输入。竞品AI行程助手（携程问道、程心AI等）的输入都是"用户主动填写或打字描述"；把微信群聊多选转发作为产品级入口，行业内没有先例。它把平台触达点从"用户打开App"前移到"用户在群里聊旅行"的那一刻。
创新2多人视角：从"给一个人订"到"给一群人成行"。现有预订链路全部是单人视角（单人下单、单人到店）；本方案原生处理人数、多间房拆分、儿童票、老人免票、均摊分账——这是多人出行才有的结构性需求，单人产品改不出来。
创新3均摊计算器内置在决策流里。美团有"拼好饭AA"，但没有"旅行级AA"；本方案把跨4个品类的均摊规则（房间拆分/儿童半价/打车均摊）做成实时计算，且随方案修改自动重算。
创新4决策回环：方案回流群聊。不是把用户锁在小程序里，而是生成可交互的方案卡片分享回群——群成员点确认、提异议，AI 在群里协商改案。决策发生在哪，产品就在哪。
创新5多品类正向交叉的天然载体。一次方案生成必然同时拉动酒店、火车票、用车、门票四个品类的订单——交叉销售不是"推荐位"，而是方案本身的组成部分。
六、实物设计（原型说明）
6.1 关键界面
1
入口层（微信侧）
群聊多选转发路径：长按消息→多选→左下角转发→最近使用小程序「程星AI」；以及程星AI小程序内「+ → 从聊天记录选择」。微信开放能力（聊天记录打开/选取）已有成熟接口，技术上可落地。
2
解析确认页（屏1）
三要素卡片（人数/日期/城市）+ 自动提取的偏好标签（住西湖边、人均600、带娃）+ AI澄清反问气泡（"2名儿童身高是否超1.2m？影响火车票和门票价格"）。每个要素可点击修改，修改后重新生成。
3
方案+均摊页（屏2）
Day by Day 行程卡（含雨天备选）+ 四品类费用明细 + 人均均摊大数字（¥1,675） + 分摊口径切换（按人头/按家庭）+ 「调整方案 / 一键预订全部」双按钮。
4
群内确认页（屏3）
方案卡片分享回群 → 群成员实时确认状态列表 → 异议成员与AI的协商对话（改Day2行程→方案V2+人均降到¥1,620）→ 一人代付或各付各的 → 自动生成按人均摊的收款与记账。
6.2 交互细节（小而关键）
解析溯源：每个识别出的要素可点开"来源"——高亮它来自聊天记录的哪一条（"8人 ← 来自张哥 10/12 21:34 消息"），建立信任。
不确定就问，不猜：置信度低于阈值的三要素，AI 用选择题形式反问，一次最多问2个问题，避免审问感。
价格口径切换：「按人头均摊 / 按家庭均摊 / 各付各的」三档一键切换，覆盖不同群的AA文化。
方案版本管理：每次群内协商改动生成 V2/V3，版本间可对比（"比V1人均省 ¥55，改了什么"）。
七、营销推广
冷启动：组织者激励
首发主打"群旅组织者"人群：组织者用群聊成行下单，获赠组织者礼包（升房券/接机券），因为他决定了全群的8个人在哪下单。
裂变：方案卡片即广告
方案卡片分享回群时自带产品露出——每一个群、每一次分享都是对"下一个组织者"的种草，天然裂变。
场景营销：节点打点
五一/十一/寒假前2周，投放"别再当人肉群旅管家"内容（小红书/抖音），直击组织者痛点，引导搜索小程序。

九、边界与风险
隐私合规（最重要）：聊天记录导入必须基于用户主动多选授权（微信侧有明确授权弹窗），仅解析选中的消息、用后即焚、不上传原文入库，只保留结构化结果。合规方案需在立项时与法务确认。
解析错误风险：用"澄清反问 + 要素可改 + 溯源标注"三重兜底，AI 不默默做决定。
非目标（Non-goals）：不做长周期群聊托管（只处理被选中的记录）；不做群内社交功能；V1 不做国际行程。
供应链依赖：方案生成的房态/票价/儿童票规则依赖各品类接口实时数据，Demo 阶段可用脱敏真实数据回放。
十、毕设汇报讲法（60秒版）
开场演示：现场打开一个有26条消息的微信群 → 多选转发到程星AI → 大屏上看 AI 抽出"8人、10.2-10.4、杭州、带娃、人均600" → 生成方案 → 人均 ¥1,675 出现的那一刻就是高光点。
痛点一句话："多人出行的决策发生在微信群里，而所有OTA只服务'打开App之后的那个人'。组织者是人肉中间件，我们用AI替换他。"
创新一句话："业内第一个把聊天记录当输入源的旅行产品；第一次把酒店、火车、用车、门票的多人均摊做进一条决策链路。"
AI价值一句话："L1解析、L2澄清、L3编排、L4均摊协商——每一层都是用户自己干不了或懒得干的事。"
收尾：切换天气/人数/偏好三个变量，方案实时重算——证明它是活的AI，不是静态页面。
