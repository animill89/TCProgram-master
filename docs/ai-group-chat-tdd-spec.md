# AI 群聊旅行页面：设计与 TDD 规格

## 目标

新增一个路由页面，模拟微信旅行群聊。用户可以浏览 mock 聊天记录，通过长按进入多选模式，选择若干条消息后分享到现有 AI 对话页面；AI 页面将选中的聊天内容带入提示词并发起分析。

本阶段只定义行为与测试，不新增业务实现代码。

## 现有能力

- 前端入口：`client/src/App.jsx`
- AI 流式接口：`client/src/api.js` 中的 `streamChat`
- AI 服务接口：`POST /api/chat/stream`
- 测试栈：Vitest + Testing Library
- 当前应用没有路由库，需要沿用项目现有的轻量路由方式，或在实现前引入最小必要方案

## 用户流程

1. 用户访问群聊路由，例如 `/group-chat`。
2. 页面展示微信风格的群聊标题、成员数、头像、昵称、时间和 mock 消息。
3. 用户长按任意聊天消息。
4. 页面进入消息多选模式，长按的消息默认选中。
5. 用户点击其他消息进行选中/取消选中。
6. 用户点击“分享给 AI”。
7. 系统按原始聊天顺序拼接选中消息，并跳转现有 AI 对话页面。
8. AI 页面使用包含聊天记录的 prompt 调用 `streamChat`，展示流式回复。

## 交互规则

### 普通模式

- 消息可正常浏览。
- 长按消息进入多选模式，并选中该消息。
- 普通点击不触发选择。

### 多选模式

- 每条消息显示可选状态。
- 点击消息切换选中/取消选中。
- 显示已选数量。
- “分享给 AI”按钮仅在至少选中一条消息时可用。
- 提供取消多选操作，取消后恢复普通聊天模式。
- 选中顺序不影响 prompt 顺序；prompt 始终按聊天记录在群聊中的时间/原始顺序排列。

### 长按实现约定

- 支持移动端 `touchstart`/`touchend` 长按手势。
- 建议长按阈值为约 500ms；短按不应进入多选模式。
- 若实现同时支持桌面端，可增加 `mousedown`/`mouseup` 兼容，但不改变移动端行为。
- 长按过程中若发生明显移动，应取消长按，避免滚动误触。

## Mock 数据约定

每条消息至少包含：

```js
{
  id: 'message-1',
  senderId: 'user-1',
  senderName: '小林',
  avatar: '/images/avatar-lin.png',
  content: '国庆要不要去杭州？',
  timestamp: '2026-08-26 20:41'
}
```

mock 对话应覆盖旅行讨论中的典型信息：目的地、日期、人数、预算、交通方式和偏好，并至少包含多位群成员。

## AI Prompt 约定

分享后传给 AI 的用户消息应包含明确任务和聊天上下文，例如：

```text
请分析以下旅行群聊记录，提取目的地、出行日期、人数、预算、交通方式和成员偏好；指出冲突或缺失信息，并给出下一步建议。

群聊记录：
[小林 2026-08-26 20:41] 国庆要不要去杭州？
[阿杰 2026-08-26 20:42] 我们一共 6 个人，预算人均 2000。
```

要求：

- 保留发送者名称和消息原文。
- 保留选中消息的原始顺序。
- 仅使用用户主动选择的消息。
- 至少生成一条 `role: 'user'` 消息后再调用 `streamChat`。

## TDD 测试清单

测试文件建议：`client/src/GroupChat.test.jsx`；路由集成测试可放在 `client/src/App.test.jsx` 或独立路由测试文件。

### 路由与渲染

- 访问群聊路由时渲染群聊标题和成员数。
- 页面渲染多条 mock 消息。
- 不同发送者消息显示对应昵称和头像。
- 消息按微信风格区分本人/他人气泡位置。

### 长按与多选

- 短按消息不会进入多选模式。
- 长按消息进入多选模式。
- 长按触发的消息默认处于选中状态。
- 多选模式显示“分享给 AI”和取消操作。
- 点击未选消息会选中该消息。
- 点击已选消息会取消选中。
- 选中状态有可访问的标识，例如 `aria-checked="true"`。
- 取消多选后，所有选择状态清除并恢复普通模式。
- 消息滑动/移动超过阈值时不应误触发长按。

### 分享与 AI 跳转

- 未选消息时“分享给 AI”按钮不可用。
- 选中一条消息后按钮可用。
- 选中多条消息后，生成的 prompt 包含发送者、时间和消息内容。
- prompt 顺序与聊天记录原始顺序一致，而不是用户点击顺序。
- 分享后进入现有 AI 对话页面。
- 分享后调用 `streamChat`，参数中包含生成的 prompt。
- AI 页面能够展示流式响应。
- 分享后群聊选择状态被清理，避免返回页面时残留选择。

### 边界行为

- 空消息或缺少内容的 mock 数据不会被拼入 prompt。
- 长消息仍可正常选择和分享。
- AI 请求失败时显示现有错误提示，不吞掉错误。
- 用户在 AI 请求进行中不能重复触发同一分享请求。

## 验收标准

- 用户无需手动复制聊天内容即可完成“长按选择 → 分享给 AI → AI 分析”。
- 选择内容、发送者信息和顺序在 AI prompt 中可验证。
- 原有首页和直接 AI 对话流程保持兼容。
- 所有新增测试先以失败状态运行，再实现最小代码使其通过。
- 前端现有测试与新增测试全部通过，且构建成功。

## 非目标

- 本阶段不接入真实微信 SDK 或微信聊天记录 API。
- 不实现群成员管理、消息持久化、撤回、已读回执和真实转发。
- 不改造后端 AI 接口协议。
- 不在本阶段实现完整的旅行订单、酒店或车票预订流程。
